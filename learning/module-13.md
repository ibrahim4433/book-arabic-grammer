# Module 13: The Cryptographic Tagger (`id_manager.py`)

## 1. Tool Definition
**What is it?** 
If the layout verifier (Module 12) detects an overflow, it needs to tell the AI exactly which HTML element caused the overflow. To do this reliably, every single grammar rule, poem box, and exam question in the book must have a unique identifier.

`Jules-workspace/id_manager.py` manages the **`bXXXXX`** ID system. It scans all 200 physical HTML files, uses the `secrets` library to generate cryptographically safe, collision-resistant IDs, and uses BeautifulSoup to automatically inject them into the HTML DOM wherever they are missing.

## 2. I/O Mapping
*   **Inputs:** 
    *   Hundreds of raw HTML files generated by the AI (e.g., `pages/02.1_topic.html`).
*   **Processes:**
    *   **Scan:** Loads all HTML files into a Python `set` to map every ID currently in existence.
    *   **Tag:** Loops through the DOM. If it finds a `<header>` or `.irab-box` without an ID, it mathematically guarantees a new unique ID and injects it.
    *   **Verify:** Checks for duplicates (e.g., if the AI hallucinated the same ID twice).
*   **Outputs:**
    *   Direct physical modifications to the HTML files on the hard drive.
    *   A CLI report detailing how many IDs were added.

*   **Lines 106-108:** `if tag_id in self.existing_ids:`

### Block D: Cryptographic ID Generation
We cannot use sequential IDs (like `id-1`, `id-2`) because multiple AI agents generate files in parallel (Module 18). They would override each other.

```python
# From Jules-workspace/id_manager.py

116:     def generate_id(self) -> str:
117:         """Generate a cryptographically random unique ID in format bXXXXX."""
118:         while True:
119:             # 5 decimal digits → 100_000 possibilities, collision-safe via set
120:             digits = "".join(str(secrets.randbelow(10)) for _ in range(5))
121:             new_id = f"b{digits}"
122:             if new_id not in self.existing_ids:
123:                 self.existing_ids.add(new_id)
124:                 return new_id
```
#### Line-by-Line Commentary
*   **Line 118:** `while True:`
    *   An infinite loop. It will keep generating random numbers until it successfully finds one that does not exist in the `existing_ids` set.
*   **Line 120:** `secrets.randbelow(10)`
    *   Unlike the standard `random` library (which is predictable), the `secrets` library hooks into the operating system's cryptographic entropy pool. This guarantees true randomness for the 5-digit string.
*   **Line 121:** `new_id = f"b{digits}"`
    *   HTML5 specs strongly advise against IDs starting with a number. The `b` prefix (for "block") ensures full CSS/JS compliance.

#### Line-by-Line Commentary
*   **Lines 128-137:** `_collect_unique_candidates()`
    *   Because our `TARGET_SELECTORS` might overlap (e.g., an element could theoretically be a `.benefit-box` *and* match `.split-grid > *`), we must deduplicate the elements in memory using Python's `id()` memory address tracking before we process them.
*   **Line 141:** It forces a full scan of the repository first. You can't safely assign new IDs unless you know what already exists.
*   **Lines 152-155:** `if not tag.has_attr("id"): tag["id"] = self.generate_id()`
    *   The surgery happens here. If an AI forgot to assign an ID to an I'rab box, BeautifulSoup dynamically injects a cryptographically safe ID directly into the DOM node in memory.
*   **Lines 157-162:** `if ids_added > 0:`
    *   An optimization. It only overwrites the physical HTML file on the hard drive (`filepath.write_text`) if an ID was actually injected. If the file was already perfectly tagged, it skips disk I/O entirely.
